Defect: The bullet sends a `metadata` given with `--file` as a part. `upload.Artifacts`' `ProcessFile` returns

- D4 "The uploads", first bullet: "(`file` and `metadata`)" → "(`file`; Workhorse generates `metadata` and refuses

### C2 — A `-f token=` job token never reaches the artifacts pre-authorization
Severity: C
Location: requirements.md § Residuals
Defect: Before the upload, Workhorse sends `POST …/jobs/:id/artifacts/authorize` through `newRequest`. That request
keeps the query and has no body (`api.go`). The endpoint runs `authenticate_job!` (`lib/api/ci/runner.rb`), and
`job_token` is `params[:token] || env['HTTP_JOB_TOKEN']` (`lib/api/ci/helpers/runner.rb`). The record's `token` row is
`In` `body`, so `call` sends it as a multipart field, and the pre-authorization never sees it. The upload therefore
authenticates only with the configured credential as `TokenType.JOB` (`JOB-TOKEN`, `transport.py`). Any other
credential is answered `forbidden!`.
Material-because: none of the five classes. GitLab's refusal exits 1, and the `Location` is AC-1.3's, which is frozen.
Proposed-edit: add one line to requirements Residuals: "`openapi-only#upload-job-artifacts` authenticates in
Workhorse's body-less pre-authorization (`POST …/artifacts/authorize`), so it needs a job token in `config/gitlab.json`
(`JOB-TOKEN`). Its `token` form field does not reach that step."

## Checked, no finding

- **Routes.** `PUT …/packages/generic/`, `…/packages/ml_models/` and `…/packages/terraform/modules/`, and
  `POST …/terraform/state/.*`, go to `requestBodyUploader`. `POST v4/jobs/[0-9]+/artifacts\z` goes to
  `contentEncodingHandler(upload.Artifacts(...))` (`routes.go`). D4's split and D5's four raw-body records match.
- **Raw body.** `processRequestBody` stores `r.Body` through `destination.Upload(..., r.ContentLength, ...)`. It then
  replaces the body with the URL-encoded `GitLabFinalizeFields("file")` and sets `application/x-www-form-urlencoded`
  (`body_uploader.go`). Each Rails endpoint reads `requires :file, type: ::API::Validations::Types::WorkhorseFile`:
  `generic_packages.rb`, `ml_model_packages.rb`, and `terraform/state.rb` through `File.read(params[:file]&.path)`.
  docs.gitlab.com "Upload module" sends `--upload-file`.
- **Query values.** Workhorse discards the original body, so only the query carries `status` and `select` to Rails.
  Grape's `params` "includes `GET`, `POST` and `PUT` parameters" (README), `generic_packages.rb` reads
  `params[:select]`, and `conventions.md`'s example sends `?select=package_file`. Reading every other row of a
  raw-body record as `Location.QUERY` (D4, AC-3.2) is right.
- **`Content-Type: application/octet-stream`.** `RequestBody` checks no media type and overwrites the header, and
  `newRequest` deletes `Content-Type` from the pre-authorization. Setting the header keeps urllib from adding its
  default ("`Content-Type: application/x-www-form-urlencoded` will be added as a default", `urllib.request.Request`).
- **Content-Length.** urllib uses "`Content-Length` ... to send bytes objects", and chunked encoding only for files and
  iterables (`urllib.request.Request`). `read_input` returns `bytes` (`read_bytes`, `sys.stdin.buffer.read()`), so
  Workhorse gets a known `r.ContentLength`. `_build_request` passes `method=`, so urllib's `POST` default for a `data`
  never replaces `PUT`.
- **No `--input`.** A Terraform state call with an empty body is answered `no_content!` and writes nothing
  (`terraform/state.rb`).
- **Job-artifacts multipart.** The part must be named `file` (`ProcessFile`). `rewrite.go` treats a part with a
  `filename` as a file and copies a part without one as a field, which is F's oracle: `file` with a `filename`, and
  `artifact_type` without. Workhorse reads `artifact_format` from `r.URL.Query()` only, but a form value still reaches
  Rails. For a form value, Workhorse runs its default (zip) branch, and that branch returns no metadata for a non-zip
  file (`CodeNotZip` → `nil, nil`). The body placement changes nothing material.
- **`read_input` as the argparse `type`.** The docs name two hazards: an exception other than the three is "not
  handled", and a `FileType` file is "not automatically closed". Neither arises here: `OSError` is raised again as
  `ArgumentTypeError`, and `read_bytes` closes the file. `sys.stdin.buffer` is the documented binary stream ("use the
  underlying binary `buffer` object").
